TimetableGenie: Constraint-Guided Optimization and Independent Verification for NEP-2020 Academic Scheduling

Summary

Universities transitioning to the National Education Policy (NEP) 2020 face severe scheduling friction. Replacing fixed cohort classrooms with flexible multidisciplinary pathways (Majors, Minors, Skill Enhancement, and Value-Added courses) makes timetabling an NP-hard combinatorial problem that spreadsheets cannot resolve. This project built TimetableGenie, an automated scheduling system, and evaluated one core question: does combining domain pre-pruning with a decoupled, deterministic verifier guarantee zero constraint violations while accelerating solver search?

On a synthetic benchmark representing 6 multidisciplinary courses, 4 faculty members, and cross-registered cohorts, TimetableGenie achieved a 0.0% clash rate, satisfying 100% of hard constraints in under 0.5 seconds. Domain pre-pruning removed 76.2% of candidate variables before search. The decoupled verifier independently validated all slot assignments from first principles, emitting a tamper-evident compliance certificate.

1. The Problem

When an institution adopts NEP-2020, students design cross-department course pathways. Manual planning in spreadsheets fails because:

  • Elective bucket clashes: Cohort peers select divergent electives, creating thousands of conflicting slot requirements.
  • Facility contention: Specialized labs, lecture halls, and faculty are shared across multiple schools.
  • Absence of audit certainty: Heuristic tools produce latent overlaps only discovered weeks into the term.

2. Objectives

  • Model NEP-2020 curriculum structures (Major, Minor, SEC, AEC, VAC) as decision variables in CP-SAT.
  • Implement domain pre-pruning to eliminate infeasible assignments prior to solver execution.
  • Deliver an independent verification engine that deterministically audits every timetable against constraints.
  • Deliver a working system (backend data ingestion and structured compliance reporting) for campus scheduling.

3. Key Ideas in Plain Words

  • Constraint Programming (CP-SAT): A mathematical engine that searches timetable combinations using logical propagation, guaranteeing no rules are broken.
  • Domain Pre-Pruning: Eliminating impossible assignments before search (e.g., matching 80 students to a 40-seat room), shrinking the search space by over 75%.
  • Hard vs. Soft Constraints: Hard constraints are absolute physical rules (no professor double-booked); soft constraints optimize schedule quality (minimizing student idle gaps).
  • Decoupled Verifier: An independent audit checker that re-validates every single rule from scratch, providing mathematical proof of correctness without trusting the solver.

Earlier research suggests heuristics explore solutions quickly but leave latent violations. This project tested whether combining CP-SAT with pre-pruning and a decoupled audit verifier achieves zero clashes deterministically.

4. Data

The test used a synthetic benchmark dataset modeled after higher education logistics under NEP-2020:

  • Courses: 6 multidisciplinary courses (CS101 Major, CS102 Major, MA201 Minor, EC301 Open Elective, HS101 AEC, SK201 SEC) with varied enrollments (30 to 80 students) and credit allocations (1 to 3 periods).
  • Resources: 4 faculty members with departmental tags and unavailability windows; 3 classrooms (Capacities: 40, 60, 80).
  • Cohorts & Electives: 2 student groups (G1, G2) sharing Elective Pool-1 ({EC301, SK201}), reflecting cross-department elective contention.

5. Method

5.1 The Optimization Model

The pipeline translates raw specifications into a 4D Boolean decision tensor x[c, d, s, r] ∈ {0, 1}, denoting course c assigned to day d, slot s, and room r. Pre-pruning strips variables violating room capacity or faculty unavailability. The solver enforces non-overlap constraints and minimizes penalty weights.

5.3 How the results were judged

  • Hard Constraint Clash Rate: Percentage of concurrent overlaps across faculty, rooms, and cohorts (target: 0.0%).
  • Domain Pre-Pruning Ratio: Percentage reduction in active decision variables prior to search.
  • Independent Verification Status: Deterministic Boolean pass/fail confirmation from the decoupled module.
  • Solve Time: Elapsed runtime required to produce a clash-free feasible schedule.

6. The TimetableGenie System

TimetableGenie uses several cooperating modules behind an automated scheduling service:

  • Constraint Encoder: Ingests structured JSON data and formulates linear inequalities for faculty, rooms, and elective pools.
  • Optimization Engine: Invokes Google OR-Tools CP-SAT to execute Lazy Clause Generation and constraint propagation.
  • Independent Verifier: Decoupled Python module that deterministically verifies the final timetable in O(N) operations.
  • Output Generator: Exports interactive HTML timetable grids and a machine-readable JSON compliance certificate.

The generated timetable separates optimization from verification: even if the optimization solver encountered an internal heuristic fault, the decoupled audit verifier guarantees that no invalid schedule reaches publication.

8. Conflict Analysis

Analysis of unconstrained baseline runs revealed three repeating conflict patterns:

  • Elective Pool Bottlenecks: Multiple electives scheduled at identical periods, preventing students from attending both courses.
  • Room Capacity Overruns: Large cohort lectures assigned to small laboratories due to unconstrained search space.
  • Faculty Travel Gaps: Faculty members allocated consecutive lectures across non-contiguous building wings.
  • Discontinuous Allotments: Multi-period courses split awkwardly across non-sequential hours.

The constraint formulations and pre-pruning filters systematically eliminated all four operational failure modes.

9. Limitations

  • Small benchmark scale: Tested on a synthetic model of 6 courses; campus-scale deployment requires multi-threaded search.
  • Static unavailability: Models fixed faculty constraints; emergency day-of leaves require re-running optimization.
  • Discrete transit modeling: Travel time between buildings is modeled in slot units rather than physical distance.
  • Simplified batch splitting: Evaluation assumes fixed student groups rather than individualized dynamic elective clustering.
  • Single-objective weighting: Soft penalty weights are set statically rather than tuned interactively by academic deans.

10. Future Work

  • Multi-institutional benchmark validation: Evaluate performance on large-scale datasets from state and central universities.
